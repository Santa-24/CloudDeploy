1. PROJECT PURPOSE & OVERVIEW
================================================================================

1.1 Core Purpose:
Modern web applications (React, Vite, Vue, Next.js static exports, Tailwind CSS)
are pre-compiled client-side static bundles (HTML, CSS, JS, media). Despite this,
hosting static sites on cloud infrastructure typically suffers from two extremes:
  1. Manual VM Inefficiency: Running full EC2 instances with NGINX/Apache incurs
     persistent server costs, requires ongoing OS/security patching, and presents
     unnecessary server-side attack surfaces for serving unchanging static files.
  2. Proprietary PaaS Lock-In: Platforms like Vercel and Netlify charge inflated
     bandwidth egress fees (up to 5x direct AWS wholesale rates), obscure raw
     cloud primitives, and lock organizations into closed proprietary ecosystems.
  3. Security Risks & Data Leaks: Public S3 bucket misconfigurations and legacy
     Access Control Lists (ACLs) regularly result in data leakage.
  4. Downtime During Rollbacks: Overwriting files in-place causes broken builds,
     and recovering from bugs requires full re-uploading and redeployment (minutes).

CloudDeploy solves these problems by providing a self-hosted, AWS-native deployment
control plane that combines the ergonomic simplicity of modern PaaS platforms with
the enterprise security, cost efficiency, and sovereign control of native AWS.

1.2 Key Architectural Pillars:
* Zero Server-Side Execution: Customer code NEVER executes on backend servers.
  Only static assets are accepted, validated, stored, and served globally.
* Origin Access Control (OAC): S3 buckets are 100% private with Block Public
  Access enforced. Only Amazon CloudFront edge distributions authenticate using
  AWS Signature Version 4 (SigV4) to fetch assets.
* Sub-Second (< 500 ms) Atomic Rollbacks: Every deployment is written to an
  immutable S3 prefix tree (`tenants/{id}/projects/{id}/builds/{id}/`). Rolling
  back to any historical release requires only updating a relational database
  pointer and dispatching a CloudFront edge cache invalidation—no files are
  re-uploaded or re-extracted.
* 14-Step Streaming Ingestion Pipeline: Streams uploaded archives directly
  through memory buffers, validates integrity, detects RFC MIME types, computes
  MD5 hashes, and parallelizes uploads to S3 with live Server-Sent Events (SSE).
* Integrated FinOps Cost Intelligence: Real-time cost modeling for S3 Standard
  storage, CloudFront edge egress, and Route 53 DNS queries with dual-currency
  projections (USD $ and INR ₹).
* Strict Multi-Tenancy: Cryptographically derived JWT tenant isolation enforced
  at both the relational database layer (Row-Level Security/foreign keys) and
  object storage prefix hierarchy.

2. SERVICES & RESOURCES USED
================================================================================

CloudDeploy utilizes an end-to-end cloud and software engineering stack:

2.1 AWS Cloud Services & Infrastructure Resources (28 Planned/Configured Components):
--------------------------------------------------------------------------------
1.  Amazon S3 (Upload Staging Bucket):
    - Name: `clouddeploy-prod-uploads-<accountId>-ap-south-1`
    - Role: Temporary storage for incoming compressed application archives (.zip).
    - Hardening: 100% Block Public Access, SSE-S3/KMS encryption, 3-day lifecycle purge.
2.  Amazon S3 (Published Static Sites Bucket):
    - Name: `clouddeploy-prod-sites-<accountId>-ap-south-1`
    - Role: Origin store for all published static web bundles.
    - Structure: Immutable versioned directory paths (`sites/{siteId}/deployments/{id}/`).
    - Hardening: Zero direct public access; access granted solely to CloudFront OAC.
3.  AWS Origin Access Control (OAC):
    - Name: `clouddeploy-prod-s3-oac`
    - Role: Cryptographic SigV4 token signing between CloudFront and S3.
    - Advantage: Replaces legacy OAI; supports all AWS regions and SSE-KMS encryption.
4.  Amazon CloudFront:
    - Distribution ID: `clouddeploy-prod-cdn`
    - Role: Global Content Delivery Network (CDN) with edge caching across 600+ PoPs.
    - Features: HTTP/2 & HTTP/3 support, Brotli/Gzip compression, TLS 1.3 termination,
      SPA error routing (rewriting 404 to index.html with HTTP 200).
5.  Amazon Cognito:
    - User Pool: `clouddeploy-prod-users`
    - Role: Tenant user directory, self-registration, SRP login, TOTP MFA, JWT issuance.
    - App Client: `clouddeploy-prod-spa-client` (public client without secret for SPA).
6.  Amazon RDS for MySQL 8.0:
    - Instance: `clouddeploy-prod-mysql` (db.t4g.small / db.t4g.micro, Multi-AZ).
    - Role: ACID transactional metadata persistence (tenants, projects, builds, audits).
    - Security: Encrypted gp3 storage, private DB subnets, inaccessible from public internet.
7.  Amazon EC2 & Auto Scaling Group (ASG):
    - Group: `clouddeploy-prod-asg` (t4g.medium ARM64, Ubuntu 22.04 LTS).
    - Role: Hosts the containerized backend control plane and deployment orchestrator.
8.  Application Load Balancer (ALB):
    - Name: `clouddeploy-prod-alb`
    - Role: Internet-facing load balancer spanning 2 Availability Zones; routes traffic
      to backend containers on port 8080 with 15-second health check probes.
9.  Amazon VPC (Virtual Private Cloud):
    - CIDR: `10.0.0.0/16` across 2 Availability Zones (AZ-a and AZ-b).
    - Subnets: 2 Public Subnets (ALB/NAT), 2 Private App Subnets, 2 Private DB Subnets.
    - Gateways: 1 Internet Gateway (IGW) and 1 NAT Gateway for private egress.
10. Layered Security Groups:
    - ALB SG: Ingress ports 80/443 from 0.0.0.0/0.
    - App SG: Ingress port 8080 restricted exclusively to ALB SG.
    - RDS SG: Ingress port 3306 restricted exclusively to App SG.
11. AWS Secrets Manager:
    - Secret: `clouddeploy/prod/rds/credentials`
    - Role: Automated generation and rotation of master database credentials.
12. Amazon Route 53:
    - Hosted Zone: `clouddeploy.dev` / `sites.clouddeploy.internal`
    - Role: Global authoritative DNS resolution and CloudFront/ALB alias routing.
13. AWS Certificate Manager (ACM):
    - Certificates: Auto-renewing wildcard SSL/TLS certificates (`*.clouddeploy.dev`).
    - Region: `us-east-1` for CloudFront edge; `ap-south-1` for regional ALB.
14. AWS WAF (Web Application Firewall):
    - Web ACL: `clouddeploy-prod-waf`
    - Role: OWASP Top 10 mitigation, rate limiting, and DDoS protection on ALB.
15. Amazon CloudWatch:
    - Log Group: `/aws/clouddeploy/prod/application` (30-day retention).
    - Role: Centralized JSON structured logs and automated alarms for 5xx errors & health.
16. Amazon SNS (Simple Notification Service):
    - Topic: `clouddeploy-prod-ops-alerts`
    - Role: Real-time operational incident notifications via Email / SMS.
17. AWS IAM (Identity & Access Management):
    - Instance Profile: `clouddeploy-prod-backend-ec2-role`
    - Role: Mathematically scoped least-privilege policies for S3, CloudFront, Secrets.

2.2 Backend Control Plane Technology Stack:
--------------------------------------------------------------------------------
* Language & Runtime: OpenJDK 21 LTS / Java 21
* Core Framework: Spring Boot 3.3.4 (with alternative Node.js/Express control plane)
* Security: Spring Security with stateless JWT filter (`JwtAuthFilter`) verifying
  Amazon Cognito tokens via JWKS endpoints
* Database ORM & Migrations: Spring Data JPA, Hibernate, Flyway (`V1__init_schema.sql`)
* AWS SDK: AWS SDK for Java v2 (`software.amazon.awssdk`: s3, cloudfront,
  cognitoidentityprovider, secretsmanager, cloudwatch, sns)
* Archive Processing: Apache Commons Compress (stream-based ZIP extraction)
* Dev / Offline Fallback: Embedded H2 database in MySQL compatibility mode and
  `LocalStorageService` for 100% offline development without an AWS account

2.3 Frontend Single-Page Application (SPA) Stack:
--------------------------------------------------------------------------------
* Framework: React 18 (18.3.1) + TypeScript 5.7
* Build Tool: Vite 5 (5.4.11)
* Styling & Design System: Tailwind CSS 3.4 with custom editorial tokens:
  - Warm Paper / Ivory: `#F5F0E7` (Primary background, surfaces)
  - Ink Black: `#1D1C19` (High-contrast text, borders, terminal badges)
  - Burnt Vermilion: `#C65336` (Primary accent, warnings, action buttons)
  - Acid Lime: `#D7EE73` (Status badges, active pills)
  - Typography: Playfair Display (Headings), Inter (UI), JetBrains Mono (Telemetry)
* Icons: Lucide React (0.469.0)
* Routing: React Router DOM v6 (6.28.0)
* Application Modules: 18 fully implemented views including:
  - Landing & Feature Showcase (`LandingPage`, `FeaturesPage`)
  - FinOps Cost Calculator (`PricingPage`)
  - Architecture Templates Hub (`TemplatesPage`)
  - Projects Management & Scaffolding (`ProjectsListPage`, `CreateProjectPage`)
  - Deployment Details & Timeline (`DeploymentDetailsPage`, `DeploymentHistoryPage`)
  - Drag-and-Drop Ingestion Dropzone (`UploadDeployPage`)
  - Usage & Quotas Monitoring (`UsageQuotasPage`)
  - Admin Operations & Failure Triage (`AdminOverviewPage`, `AdminUsersPage`, etc.)
  - Real-Time SSE Telemetry Stream integration

2.4 DevOps, Containerization & Infrastructure-as-Code:
--------------------------------------------------------------------------------
* Container Runtime: Docker 27.2 & Docker Compose
* Multi-Stage Builds:
  - Frontend: Compiled via Node 20 Alpine -> packaged into NGINX container (28 MB)
  - Backend: Compiled Java JAR -> packaged into Eclipse Temurin 21 JRE Alpine (142 MB)
* Reverse Proxy: NGINX 1.25 Alpine with TLS termination, gzip/brotli compression,
  security headers (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`)
* Infrastructure as Code (IaC): Modular AWS CloudFormation templates:
  - `main.yaml`, `vpc.yaml`, `security.yaml`, `rds.yaml`, `compute.yaml`,
    `storage-cdn.yaml`, `monitoring.yaml`
* Automation Scripts:
  - `setup-aws.ps1`: Automated AWS provisioning via CLI
  - `cleanup-resources.ps1`: Safe teardown of cloud resources
  - `generate_report.py`: Automated generator for academic project report (.docx)
  - `generate_presentation.py`: Automated generator for 14-slide presentation (.pptx)
